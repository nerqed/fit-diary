# Forma — дорожная карта MVP

Обновлено **24 ноября 2026**. Текущий этап — **v0.3.1, упрощение тренировок и прогресса** по итогам использования v0.3.0 на iPhone. Затем запланирован MVP-2.

## Принципы низкого трения для всех этапов

- Повседневная запись укладывается в 1–2 тапа и ориентировочно 10 секунд. По умолчанию предлагать последнее значение, подсказку, вчерашний вариант или избранное.
- Сохранять неполные записи. Давать дополнить любой прошлый день и пересчитывать статистику.
- В будущем считать только недельный стрик, N дней из 7, без обнуления при пропуске. Ежедневный стрик с обнулением запрещён.
- Нейтрально показывать цифры, без красного за превышение или недобор.
- Профиль необязателен, онбординг не блокирует действия.
- Уведомления можно отключить, максимум одно в день.
- Дополнительные поля RIR, заметок и будущих замеров скрыты до включения в настройках.

## MVP-1 — тренировки и прогресс

ИИ и сеть для ведения тренировок не требуются.

- [x] SQLite: expo-sqlite 58.0.17 для SDK 58, версия схемы через user_version, атомарные миграции, внешние ключи, очередь операций.
- [x] Справочник из 36 упражнений на русском с синонимами и стабильными IDs; собственные упражнения, правка и архивирование.
- [x] Шаблон: название, необязательный день недели, упорядоченные упражнения, план повторений и необязательного веса. Создание, правка, удаление, копирование с новыми IDs.
- [x] Сессия из снимка шаблона: факт веса/повторений, завершённость подхода, сохранение незавершённого занятия. Правка/удаление шаблона не меняет историю.
- [x] Повторный старт с тем же ID и повторная запись подхода не создают дубликаты. Одновременно допускается одна активная сессия; её можно продолжить.
- [x] Таймер хранит абсолютное время окончания; остаток пересчитывается после возврата/перезапуска, без зависимости от фонового JavaScript-интервала.
- [x] Рядом с подходом доступны данные предыдущей завершённой сессии этого упражнения. Сопоставление по стабильному ID, порядку вхождения упражнения и номеру подхода.
- [x] История упражнения, точки лучшего веса при фиксированных повторениях, объём (вес × повторения) и личные рекорды. Незавершённые занятия не входят в рекорды; неизвестные значения не становятся нулями.
- [x] Полная JSON-копия данных MVP-1: версии формата/схемы, даты, часовые пояса, упражнения, шаблоны, сессии и подходы. Проверка структуры, ссылок, значений и лимитов до изменения базы.
- [x] Перед импортом создаётся постоянная резервная копия; затем замена одной транзакцией. Ошибка копирования/восстановления не уничтожает текущие записи; повторное восстановление не размножает IDs.
- [x] Адаптеры системного выбора файла и меню экспорта: expo-document-picker, expo-file-system, expo-sharing. После закрытия меню экспорта не утверждаем, что пользователь сохранил файл в «Файлы».
- [x] Контроллер и новые контракты для библиотеки тренировок, редактора шаблона, сессии, истории упражнения и резервных копий.
- [x] Проверены TypeScript приложения/тестов и 29 автоматических тестов, включая настоящую SQLite. Это не проверка нативного модуля на iPhone.

- [x] Календарь поддерживает ретроввод. Вес тела, тренд за семь дней, прогрессия нагрузки и личные рекорды используют реальные записи. В копию v2 включены все новые данные, поддержан импорт v1.

### Приёмка MVP-1

Создать/скопировать/изменить шаблон → провести занятие офлайн → закрыть и открыть приложение → продолжить с сохранёнными подходами/таймером → завершить → в следующем занятии увидеть прошлые веса → открыть графики и рекорды → экспортировать файл → восстановить после резервирования → повторить импорт без дублей. Проверить отмену выбора файла, повреждённый/чужой JSON и ошибку записи резервной копии. На устройстве пока не подтверждено.

База — источник истины. Объём обозначает внешнюю нагрузку в кг × повторения, а не массу тела или физиологическую работу. Для графика лучшего веса выбирается фиксированное число повторений; 1RM не оценивается. Частичный объём показывается с полнотой данных.

## MVP-2 — питание по фото · Запланирован после проверки MVP-1

Сейчас добавлены только типы интерфейса редактора, справочника, результата распознавания и очереди. Камера, каталог продуктов, очередь, расчёт питания и мок-адаптер пока не реализованы.

- [ ] Единый редактор приёма пищи: позиции {название, граммы, источник, approximate}, изменение массы шагом 5–10 г и вручную; замена/переименование через поиск справочника, удаление, добавление поиском или текстом.
- [ ] Детерминированный расчёт из значений на 100 г: ккал/Б/Ж/У/клетчатка/витамины/минералы, мгновенный пересчёт при правке. `null` — нет данных, не 0. Частичная сумма и её покрытие не выдаются за полный итог.
- [ ] Ручной ввод и КБЖУ с этикетки на 100 г работают тем же редактором, с сохранением источника каждого значения.
- [ ] Начальный встроенный JSON: 200–300 частых российских продуктов/блюд — крупы, мясо, яйца, молочка, овощи, фрукты, хлеб, масла, соусы, напитки. Русские имена/синонимы, состояние сырой/готовый/как продаётся, единицы, микроэлементы и источник каждой строки.
- [ ] Адаптер распознавания: вход — фото, выход — JSON [{name, grams, confidence}]. До выбора провайдера — явно обозначенный мок, не анализирующий реальное фото. Провайдер не должен требовать переделки экрана.
- [ ] Фото без сети/провайдера копируется в постоянное локальное хранилище и очередь «на распознавание». Ручное заполнение доступно сразу. Повтор/отмена и защита от дублей; восстановление очереди при открытии приложения.
- [ ] Экспорт/импорт расширен до полной копии питания и очереди с новой версией формата. Отдельно решить включение локальных фотографий; не считать ссылки на исчезнувшие файлы резервной копией.

### Подготовка пищевого справочника — до реализации расчётов MVP-2

Основа — «Химический состав российских пищевых продуктов» Скурихина/Тутельяна. Зафиксировать конкретное издание, пригодный оригинал, страницу/таблицу/строку и условия включения данных. Издание 2002 г. подтверждено [каталогом РГБ](https://search.rsl.ru/ru/record/01001844793), но исходные таблицы для извлечения и условия распространения JSON ещё не подтверждены. **Не создавать вымышленные 200–300 строк под видом книжного справочника.**

Проверить г/мг/мкг, десятичные запятые, пропуски, «следы», основу на 100 г и состояние продукта. Сверить выборку с оригиналом, приложить отчёт. USDA и FatSecret не использовать. Если источник не позволяет достоверно заполнить нутриент, сохранять null, а не дополнять похожим продуктом незаметно.

### ИИ и внешние источники

ИИ распознаёт продукт, массу и текст этикетки. Все суммы, порции и рецепты рассчитывает код. Перед сохранением доступно исправление; факт сохранения подтверждается приложением. Оценка массы и источник пищевой ценности — разные данные.

Перед подключением Gemini либо HTTPS-моста Codex на VPS проверить доступность для аккаунта/региона, условия использования, фото, структурированный JSON, лимиты и ошибки. Подписка не считается автоматической оплатой приложения; запасной платный маршрут не включается. Ключи вводятся пользователем, хранятся в Keychain, не в исходниках/логах/экспорте. Смена Base URL не отправляет старый ключ новому адресу. Пока выбран только контракт адаптера.

Open Food Facts и каталоги магазинов — последующее расширение, не блокирующее MVP-2. Сохраняется порядок для упакованных товаров: личная база → OFF → каталог магазина при наличии VPS → этикетка. Каталоги «Пятёрочки»/«Магнита» допускаются только через отдельный необязательный адаптер на VPS с мостом ИИ. Перед выбором неофициальных pyaterochka_api/magnit-api проверить конкретный проект, поиск по штрихкоду, КБЖУ именно на 100 г, условия и ограничения. При недоступности шаг пропускается. Источник магазина — `store`, OFF — `off`, этикетки — `label`; подтверждённые личные сведения не перезаписываются автоматически.

## После MVP — отложено

**Этап 1.2: XP, задачи дня, стрик, достижения и coachHint отложены. Ничего из этого сейчас не реализуется.**

Также вне текущего MVP: полноценный чат и веб-поиск провайдера, автоматические предложения программы/целей, утренняя сводка за вчера в 07:00, облачная синхронизация, Apple Здоровье и расширение каталогов. Порядок уточняется после двух MVP.

Сохранённые условия: календарь только внутренний, без системного Календаря iOS; напоминания — отдельный механизм расписания с локальным часовым поясом; HealthKit сначала проверить отдельной сборкой с конкретным профилем E Sign; облако необязательно. Не диагностировать дефициты и не назначать лечение.

## История и правила выпуска

Этапы 0/1/1.1 выполнены как организация, установленный каркас и контракты. Установка v0.1.1 через E Sign заработала после Server → Local; владелец подтвердил запуск и работу вкладок. [Предыдущая дорожная карта](docs/ROADMAP-pre-MVP.md) сохранена для истории, её порядок больше не является рабочим.

Сборка остаётся в GitHub Actions на закреплённых macOS/Xcode, unsigned IPA без EAS и сертификатов. Запуск только по тегу или вручную; на обычные коммиты macOS не запускается. Опубликованный IPA не заменяется.
