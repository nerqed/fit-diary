## Этап 2 — локальный дневник · Запланирован

Профиль и история параметров с датами, ручной ввод продуктов и еды, календарь, редактирование задним числом, SQLite. Неизвестные сведения спрашиваем или оставляем пустыми.

Экспорт и импорт JSON вводятся вместе с первым сохранением реальных данных. Экспорт включает версию формата, постоянные IDs, даты/часовой пояс, единицы, источники и версии пищевой ценности. Секреты не экспортируются. Импорт проверяется до изменения базы, создаёт резервную копию текущих данных и заменяет данные транзакционно после подтверждения. Ошибка не изменяет базу; повторный импорт не создаёт дубликатов.

## Этап 3 — тренировки · Запланирован

Программа, план/факт подходов, предыдущие рабочие веса, сложность, замена упражнения, таймер отдыха и продолжение незавершённого занятия. Сохранение работает офлайн; устойчивые IDs защищают от повторной записи. Напоминания — отдельный механизм расписания с часовым поясом.

## Этап 5 — помощник · Запланирован

**Первая задача: проверка выбранного провайдера ИИ. Выбор делает владелец перед этапом 5.**

Варианты: (а) HTTPS-мост Codex CLI на VPS с авторизацией по подписке и секретным токеном; (б) Gemini API напрямую из приложения. Домашнего ПК у владельца нет. Разные протоколы реализуются отдельными адаптерами, не предполагается универсальность одного Base URL.

Проверить доступность для аккаунта и региона, условия использования выбранного размещения, текст, фото, структурированный ответ, лимиты, ошибки и отсутствие автоматического платного резервного маршрута. Пока проверки не проведены, работоспособность и отсутствие дополнительных расходов не утверждать. Россия отсутствовала в проверенном 14.11.2026 [списке Gemini](https://ai.google.dev/gemini-api/docs/available-regions); состояние требуется проверить заново перед выбором.

Настройки: тип провайдера, HTTPS Base URL, модель, ключ/токен и проверка подключения. Ключ хранится в Keychain, не в исходниках/логах/экспорте. Смена Base URL не отправляет старый ключ новому адресу автоматически.

При недоступности провайдера запросы и фотографии остаются в локальной очереди с повтором/отменой; дневник не блокируется. Повторы проверяются при открытии приложения. Не обещать постоянную фоновую работу iOS.

История читается через разрешённые функции приложения из SQLite. Модель готовит предложения; фактическую запись подтверждает приложение. Цели и программа изменяются только после подтверждения владельца. Не диагностировать дефициты и не назначать лечение.

## До этапа 6 — русский справочник · Запланирован

Отдельная задача: «Химический состав российских пищевых продуктов», Скурихин/Тутельян → версионированный JSON с русскими названиями, синонимами и микронутриентами.

Сначала подтвердить конкретное издание, пригодный исходный материал и условия извлечения/включения данных. Издание 2002 г., ISBN 5-94343-028-8, подтверждено [каталогом РГБ](https://search.rsl.ru/ru/record/01001844793), но источник для извлечения и условия распространения JSON пока не подтверждены.

Сохранить ссылки на таблицу/страницу, основу на 100 г, состояние продукта, единицы и смысл исходных обозначений. Проверить десятичные запятые, г/мг/мкг, сдвиги колонок, пропуски, «следы» и `<…`; сверить выборку с оригиналом и приложить отчёт. Это не препятствие для этапов 0–3.

## Этап 6 — питание по фото · Запланирован

Российские продукты, в том числе ассортимент «Пятёрочки» и «Магнита». **USDA и FatSecret не использовать.**

Порядок источников:
1. Личная локальная база продуктов по штрихкоду и собственных рецептов.
2. Штрихкод → Open Food Facts → кэш в личной базе с источником.
3. Нет карточки → фото этикетки «на 100 г» → распознавание ИИ → подтверждение → запись со штрихкодом.
4. Без упаковки → встроенный русский справочник.
5. «Мой рецепт»: ингредиенты, массы и выход приготовленного блюда → расчёт на 100 г.
6. Последний вариант — оценка ИИ с пометкой «примерно».

Неприменимые шаги пропускаются. У каждого нутриента хранится источник/версия/единица/основание расчёта; способ определения массы порции хранится отдельно. Неизвестное значение — «нет данных», не ноль. Микронутриенты похожего продукта нельзя подставлять в брендовый продукт незаметно. Обновление карточки не переписывает прошлые приёмы пищи. Итоги считает код, не модель.

Для [Open Food Facts](https://openfoodfacts.github.io/openfoodfacts-server/api/) сохранить атрибуцию/условия ODbL, обработать лимиты и проверить покрытие на реальных штрихкодах. Найденная карточка не гарантирует точность.
