# Форма / Forma

Личное приложение на русском для iPhone: питание, тренировки и прогресс. **Текущий приоритет — MVP-1: тренировки. Логика и контракты подготовлены; рабочие экраны подключит дизайнер.** Затем — релиз на проверку владельцем и MVP-2: питание по фото. Игровые механики отложены до после MVP.

Новые возможности пока доступны только в исходниках: существующие экраны остаются демонстрационными. Нового IPA MVP-1 ещё нет. [Передача дизайнеру](docs/MVP1-HANDOFF.md) описывает точки подключения и проверку на телефоне.

Первая опубликованная сборка: **[Forma 0.1.1](https://github.com/nerqed/fit-diary/releases/tag/v0.1.1)**. Скачайте `Forma-v0.1.1-ed677bfb00f7-unsigned.ipa` из Assets. Сборка и автоматические проверки прошли. Владелец подтвердил установку через E Sign и открытие приложения с вкладками на iPhone; полная проверка навигации и авиарежима ещё не завершена.

## Скачать и установить — только с iPhone

Компьютер, Xcode и Expo Go вам не нужны.

1. Откройте [GitHub Releases](https://github.com/nerqed/fit-diary/releases) в **Safari**. Если GitHub запросит вход, используйте аккаунт с доступом к репозиторию.
2. Откройте нужную версию и раздел **Assets**. Скачайте файл `Forma-v…-unsigned.ipa`, а не архив `Source code`.
3. Найдите скачанный IPA в приложении **«Файлы»**, обычно в папке «Загрузки».
4. Импортируйте скачанный файл в **E Sign** через выбор файла или меню «Поделиться».
5. В E Sign выберите свой действующий сертификат и совместимый профиль, подпишите приложение вместе с вложенными библиотеками и установите его.
6. Запустите **«Форма»**. При обновлениях сохраняйте bundle ID и совместимую идентичность подписи.

При подписи оставьте исходную минимальную версию iOS: **16.4**. Не включайте «Понизить требуемую версию iOS до 10.0» и другие изменения совместимости: для iPhone 15 Pro Max / iOS 26.6.1 они не нужны.

Если в E Sign подпись завершилась, но кнопка «Установить» вообще ничего не делает: откройте **Настройки → настройки подписи по умолчанию → Адрес установки / Install address**, переключите **Server → Local**, затем повторите установку уже подписанного приложения. Этот способ проверен владельцем в E Sign 5.0.2: установка завершилась, «Форма» открылась. Это решение конкретного случая, а не гарантия устранения любой ошибки установки.

Названия кнопок E Sign могут отличаться между версиями. Сертификат и пароль к нему остаются у вас: репозиторий и сборка их не запрашивают. Не вставляйте GitHub-токен в ссылку и не передавайте его E Sign — скачайте файл через авторизованный Safari.

SHA-256 в описании релиза относится к **исходному неподписанному IPA**. После подписи контрольная сумма изменится. Установка и срок действия подписи зависят от вашего сертификата и способа подписи.

## Сборка без компьютера владельца

Выпуск полностью выполняется в GitHub Actions. Для повторного запуска существующего тега можно открыть **Actions → Release unsigned iOS → Run workflow** в браузере, выбрать основную ветку и указать существующий тег вида `v0.1.1`. Новый выпуск подготавливает разработчик.

Закреплённая среда:

| Компонент | Значение |
| --- | --- |
| Runner | `macos-26`, arm64 |
| Xcode | `26.6`, build `17F113` |
| DEVELOPER_DIR | `/Applications/Xcode_26.6.app/Contents/Developer` |
| Node.js | `22.23.4` |
| Expo | SDK 58, `expo@58.0.25` |
| Имена target/scheme/product/binary | `Forma` |
| Bundle ID | `com.nerqed.forma` |
| CFBundleDisplayName | `Форма` |

Путь: `npm ci` → `expo prebuild -p ios --no-install` → `pod install` → `xcodebuild archive` (Release, iphoneos, `CODE_SIGNING_ALLOWED=NO`) → `Payload/Forma.app` → ZIP → `.ipa`.

JS-бандл и ресурсы включаются в приложение. Metro используется как сборщик в CI, но сервер Metro не нужен при запуске установленного приложения. EAS, сертификаты, provisioning profiles и `xcodebuild -exportArchive` не используются.

Сборка запускается **только** по тегу `v*` или вручную; обычные коммиты не расходуют минуты macOS. Сначала идут проверки на Linux и проверка уже существующего релиза. Версия Xcode проверяется точно; незаметного переключения на другой Xcode нет.

GitHub обновляет содержимое образа `macos-26`: это закреплённое семейство ОС, а не неизменяемый снимок. Фактический `ImageVersion` записывается в отчёт. Доступные минуты и ограничения Actions зависят от аккаунта; бесплатность не предполагается.

## Границы для разработчиков

- `src/navigation/` — маршруты и навигация.
- `src/contracts/screens.ts` — типизированные данные и действия экранов для дизайнера.
- `src/mocks/demo.ts` — явно обозначенные примеры; не личные записи и не рекомендации норм питания.
- `src/features/` — композиция и логика вне отображения.
- `src/data/sqlite/` — версия схемы, миграции и репозиторий тренировок; `src/data/exercises.ts` — 36 русских упражнений.
- `src/features/workouts/` — модель, контроллер, история, рекорды и расчёт таймера; `src/features/backup/` — JSON и системные окна «Файлы».
- `src/contracts/workouts.ts` — рабочие контракты MVP-1; `src/contracts/mealEditor.ts` — только будущие контракты MVP-2, без реализации питания.
- `src/theme/tabIcons.ts` — карта SF Symbols для вкладок. Все значения пока `null`; символы выбирает дизайнер. Навигация уже читает эту карту.
- **`src/screens/` и `src/theme/` — зона дизайнера. Здесь только заглушки, дизайн не выполняется.**

Экраны не обращаются напрямую к базе, сети или модели. Дизайнер может заменить заглушки, сохранив экспортируемые контракты. Неизвестные сведения о владельце не заполняются догадками.

Что доступно в контрактах этапа 1.1:

- «Сегодня»/«Дневник»: цель, дневные нормы и съедено, приёмы пищи с датой/часовым поясом, способом ввода, фото и блюдами в граммах.
- Каждый нутриент содержит `key`, `label`, `unit`, `amount`, `target`, источники и признак приблизительности. `amount: null` нельзя заменять на 0. При неполном покрытии `knownAmount` — только известная часть; `coverage` объясняет её полноту. `dayNutrition.dataCoverage` считает нутриенты с полными, частичными и отсутствующими данными, а не достижение пищевых норм.
- Тренировка: день, упражнения, план/факт подходов и таймер отдыха; прогресс: точки веса и лучшие рабочие веса при фиксированном числе повторений.
- Помощник: четыре состояния и сообщения; профиль: числовые поля, выбор, текст и отдельные редактируемые параметры расчёта нормы.

Совместимые поля приёмов пищи `name`, `time`, `foods` оставлены для текущих заглушек и выводятся из структурированных данных. Не редактировать эти представления как независимые записи. Действия экранов передаются callbacks из контейнеров; на этапе 1.1 это демонстрация без сохранения и запросов к ИИ.

Для предварительного просмотра доступны `demoMeals`, `demoDayNutrition`, `demoWorkout`, `demoWeightHistory`, `demoExerciseBests`, `demoAssistantStates`, `demoProfile` и `emptyProfile`. Заполненный профиль — вымышленный пример; текущая заглушка получает пустой профиль. Фото в моках — встроенная маленькая заглушка, не изображение реальной еды.

Для иконок закреплён `expo-symbols@58.0.5`, соответствующий локальной матрице Expo SDK 58 и [документации Expo Symbols](https://docs.expo.dev/versions/v58.0.0/sdk/symbols/). Нативная работа нового модуля будет проверена при следующей разрешённой сборке после передачи экранов.

Для логики MVP-1: **`npm run typecheck`** проверяет приложение и тесты, **`npm test`** проверяет хранение, резервирование, контроллер и аналитику. Тесты выполняют SQL через настоящую SQLite (`node:sqlite`), но не заменяют проверку Expo на iPhone. Эти действия не требуются от владельца iPhone.

Сборка и новый релиз ждут подключения рабочих экранов дизайнером. Старая договорённость «только typecheck» относилась к этапу 1.1.

SQLite хранится локально в контейнере приложения. Полная JSON-копия MVP-1 содержит упражнения, шаблоны, сессии и подходы; это незашифрованный файл, без ключей ИИ. Перед импортом копия текущих данных записывается и проверяется в постоянной папке приложения; её можно отдельно экспортировать через системное меню. Закрытие меню экспорта не подтверждает сохранение пользователем в «Файлы».
