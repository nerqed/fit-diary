# MVP-1: подключение логики к экранам

Статус на 17.11.2026: логика готова, интерфейс не подключён. `src/screens/` и `src/theme/` в этой работе не менялись. Не заменять пользовательские записи данными из `src/mocks/demo.ts` и не называть текущий демонстрационный IPA готовым MVP.

## Точки входа

| Задача | Модуль |
| --- | --- |
| Типы данных и репозиторий | `src/features/workouts/model.ts` |
| Открыть контроллер на iPhone | `openWorkoutController()` из `src/features/workouts/device.ts` |
| Подписка на состояние | `controller.subscribe`, `controller.getSnapshot` для React `useSyncExternalStore` |
| История/графики/рекорды | `controller.getProgress(exerciseId, fixedReps)` |
| Сессия и прошлые подходы | `controller.getSessionView(sessionId, Date.now())` |
| Экспорт/импорт/список копий | `openWorkoutBackupService()` из `src/features/backup/deviceService.ts` |
| Props рабочих экранов | `src/contracts/workouts.ts`, также экспортируются из `src/contracts/screens.ts` |

Контейнер открывает singleton контроллер и передаёт экранам данные/callbacks. Экран не читает SQLite и не вызывает модель ИИ. При ожидании показывать loading, при ошибке — ошибку и повтор, при `pending > 0` не выдавать операцию за завершённую. Состояние обновляется после подтверждённого сохранения в репозитории. Ошибка отклоняет Promise; обработчик экрана должен её обработать.

## Шаблоны и упражнения

`controller.newTemplate()` и `controller.newExercise()` создают пустые **несохранённые** черновики. Пустое название и шаблон без упражнений/подходов не сохраняются. Редактор управляет черновиком; `saveTemplate` / `saveExercise` подтверждает запись.

Порядок массивов `exercises`/`sets` — порядок выполнения. Для новых строк брать `controller.newId()` один раз при создании, сохранять ID при правке и перестановке. Сохранение выполняется целым шаблоном. День недели необязателен. Вес плана nullable; ноль означает известную нулевую внешнюю нагрузку.

Копирование: `copyTemplate(templateId, copyId)`. При повторе одного намерения использовать прежний `copyId`, а не генерировать новый. Аналогично `startSession(templateId, sessionId)`: ID создаётся один раз при нажатии/подтверждении и повторно используется при повторе запроса. Повторный старт не создаёт второй сеанс. Если уже есть активная сессия, предложить продолжить её; одновременно активна одна.

Справочник: названия и aliases из `state.data.exercises`. Собственные упражнения имеют `origin: custom`; имя/синонимы редактируются, вместо удаления использованного упражнения применяется `archived: true`. Встроенные строки защищены от изменения. История связывается по ID; старое название остаётся в снимке занятия.

## Сессия

`updateSet(sessionId, setId, {actualReps, actualWeightKg, completed})` сохраняет факт по стабильному ID. Не копировать план веса в факт автоматически. Неизвестное значение — null. Выполненному подходу нужны положительные фактические повторения. Закрытие экрана не завершает занятие: оно остаётся активным и восстанавливается из базы. `finishSession(id, completed|abandoned)` завершает его и очищает таймер.

`getSessionView` добавляет к каждому подходу `previous`: прошлую завершённую сессию, фактические вес/повторения. При нескольких одинаковых упражнениях сопоставляются их вхождение и номер подхода. Если подхода в прошлой сессии нет, значение null; не подставлять соседний подход или план.

Отдых: `startRest(id, seconds)` / `stopRest(id)`. Хранится ISO deadline. Интервал интерфейса лишь обновляет `Date.now()` для отображения; при возвращении/перезапуске остаток пересчитывается. Звук/фоновое уведомление таймера пока не реализованы.

## Прогресс

`getProgress` возвращает history, bestWeights и records. График bestWeights сравнивает один `fixedReps`; null — разрыв, не нулевая точка. Объём берётся из `history[].volume`: `amountKgReps` — только полный итог, `knownAmountKgReps` — известная часть, state — complete/partial/missing. Рекорд объёма требует полной информации. Активные и брошенные занятия в рекорды не входят. Формула 1RM не используется.

## JSON и «Файлы»

1. `exportAndShare()` записывает постоянный JSON и открывает системное меню; результат `share-sheet-closed` не равен «сохранено в Файлы».
2. `selectImport()` открывает выбор файла, возвращает null при отмене или `{name, text, preview}` после проверки. **Этот вызов базу не меняет.**
3. Показать имя файла, дату/количество записей и подтверждение полной замены данных.
4. После подтверждения вызвать `restore(selected, 'replace-all')`. Прямо перед заменой в одной очереди снимок текущей базы записывается в постоянный JSON и перечитывается; затем база заменяется транзакционно.
5. При успехе получить `recoveryFile`; показать путь/кнопку экспорта этой копии. `list()` и `share(file)` дают доступ к созданным копиям. После восстановления общий контроллер обновляется.

Лимит JSON — 16 МиБ UTF-8, formatVersion/schemaVersion — 1. Неизвестные версии/поля, дубликаты IDs, разорванные связи, некорректные даты и значения отвергаются. Поддерживается только полная копия данных текущего MVP-1; будущие фотографии/питание потребуют новой версии формата. Не выводить содержимое копий в логи и не отправлять его в ИИ.
